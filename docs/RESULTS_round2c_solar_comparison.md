## 3. ReuseGate in SOLAR's setting (label-free demand admission, defined before any result)

Decision rule fixed in advance: a claim that ReuseGate beats SOLAR needs the 95% interval of its gap to the best SOLAR variant to exclude 0.

| comparison at K = 10 | gap in F1 [95% CI, paired] | verdict |
|---|---|---|
| ReuseGate minus SOLAR | -0.016 [-0.030, -0.003] | SOLAR better |
| ReuseGate minus SOLAR-A | -0.008 [-0.021, +0.005] | not distinguishable |
| ReuseGate minus SOLAR-E | -0.006 [-0.020, +0.008] | not distinguishable |
| ReuseGate minus FIFO | +0.012 [-0.001, +0.026] | not distinguishable |

**Reading.** In the agent-memory setting of the SOLAR paper the label-free ReuseGate rule is above FIFO by 5% but not significantly; it is significantly below full SOLAR (gap in the table) and not distinguishable from SOLAR-A and SOLAR-E. These SOLAR variants use the like/dislike signal derived from the answer's F1, which ReuseGate does not use. No claim is made that ReuseGate beats SOLAR there. A learned ReuseGate was not attempted because each session offers only about 160 warm-up examples.

## 4. SOLAR as an adapted baseline in the semantic-cache streams (our setting)

The paper's SOLAR is built for an agent's experience memory with a graded feedback score. A response cache has no such score, so the regret signal is adapted (1 for a miss, 1 - cosine for a hit; no labels). Two ports are reported: the first reimplementation (parameters tuned on tuning windows only) and a port with the constants of the authors' code (no free parameters). Score = correct-hit % minus lambda x false-hit %, mean over cache capacities and evaluation windows.

## 5. How the first SOLAR reimplementation differed from the authors' code

| element | authors' code | first reimplementation (round 2c cache streams) |
|---|---|---|
| regret signal | experience mode: 1 - feedback score of the agent's answer (F1) | 1 for a miss, 1 - cosine for a hit |
| threshold | tau = clip(sqrt(2 lambda / L_hat), 0.1, 5), lambda = 5, L_hat = EMA(0.7/0.3) of 2 x std of the last 30 regrets, initial 2.236 | tuned lambda, L from a running mean |
| Beta prior | optimistic (2, 1) | (1, 1) |
| decay | beta += 0.05 every 5th retrieval for entries not retrieved | beta += 0.05 every K requests |
| eviction bonus | 0.3 x novelty from L2 distances to 2 neighbours | gamma / (1 + age / Delta) |
| SOLAR-A eviction | 0.4 exp(-age/100) + 0.3 frequency + 0.3 diversity | frequency + recency + novelty, equal weights |
| bootstrap | store everything while fewer than min(max(K/2, 5), 25) entries | store until full |
The port with reference constants (`SolarOfficialPolicy`) follows the authors' code on all of these except the regret signal, which has to be adapted.

## 6. Limitations to state

* Qwen3-4B stands in for GPT-4o-mini; only K = 10 on LoCoMo is complete; DialSim, K = 20/50/100 and the Qwen3.8-27B rerun were not obtained.
* The label-free ReuseGate in SOLAR's setting is a simple demand rule, not the learned model.
* SOLAR in the cache streams is an adaptation (no graded feedback score); its constants are the authors' except the regret signal.
* TripClick was not rerun with SOLAR (needs a data token); LmArena was not rerun with the reference-constants port.
* AUTO and SCION themselves are not reproducible without their offline training traces; a best-in-hindsight bound over the implementable portfolio members is reported instead (`docs/RESULTS_round2c_extra_baselines.md`).
